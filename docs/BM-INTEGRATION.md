# B&M Christmas integration

Six bilingual departments use the common retailer → collection → group → department → All / NEW / Today's NEW navigation. B&M currently sells these products in-store; the official listed availability is not a promise of inventory at a particular store.

Collection reads the five official public storefront search directories from the actual B&M browser origin in a single Firecrawl basic scrape. Wreaths and garlands share a source directory. No Referer or Origin is forged; only customer-facing product fields are retained. The source index supplies the complete product description, specifications, NEW state, visible WAS/RRP promotions and native gallery. There is no per-product paid detail fetch. The first successful source collection cost one credit; three initial diagnostic scrapes cost three credits. Subsequent observed pricing depends on the Firecrawl receipt, not an unlimited fixed-price guarantee.

Exact productcode is the SKU; productcodebm is a parent code. Distinct colour variants with the same parent must not be merged. Source category totals and exact records are reconciled before a snapshot is accepted. Native photos are byte-preserving and content-addressed. All gallery links remain available; the first three photos are cached for preview selection, with ETag/Last-Modified conditional revalidation for each new source snapshot; repeats of the same observation reuse the verified bytes. Local CLIP and saved assistant image/description reviews do not spend Firecrawl credits. Reviews apply only to the exact saved photo hash. Source family photos with conflicting explicit heights are labelled reference images, not asserted to depict a different exact size.

Physical-product classification excludes tree skirts, edible chocolate and installation hooks from the six requested statistics while preserving them under related source products. Tinsel is a garland, while miniature wreath-shaped tree ornaments stay in tree decorations. Colour reviews describe the dominant product colours, excluding packaging, backgrounds and unrelated display props. Height ranges remain ranges and do not become fabricated exact measurements. Unspecified materials stay unspecified.

The first complete snapshot seeds the notification baseline. Existing NEW products appear in NEW but do not become Today's NEW or trigger a baseline email flood. Beijing midnight removes a product from Today's NEW while retaining NEW history. Existing confirmed owner subscription is extended once to the six B&M scopes, without silently re-enrolling an opted-out owner. Retailer-prefixed durable keys and pinned native attachments prevent collisions and duplicate sends. Individual SKU evidence failures are deferred without stopping healthy SKU notifications.

Cloudflare's existing independent 07:00 Beijing clock dispatches bm.yml daily. The clock has at most three attempts per day, spaced at least fifteen minutes; a completed source scan stops further dispatches for that day. Delivery follows source and attachment verification, so 07:00 is the start time, not an inbox arrival guarantee. Paid requests use the existing shared 60/run, 1500/month, 5000-account-reserve policy. Activation, local image verification and source-free canonical site publication perform no Firecrawl source reads.

Validation: scripts/test-bm.mjs and scripts/test-bm-mail.mjs cover exact variants, image identity, non-Christmas/accessory exclusion, source completeness, historical filename decimals, family-size notices, source reduction visibility, height ranges, Beijing midnight, baseline isolation, retailer namespace collisions, owner scope handling, bounded clock and source-free publication. Run the full npm test before deployment.
